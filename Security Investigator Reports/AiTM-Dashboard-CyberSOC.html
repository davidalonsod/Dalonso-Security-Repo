Hunting queries used

Q7 · Token replay — same SessionId across countries

SigninLogs
| where TimeGenerated > ago(30d)
| where ResultType == 0
| extend Country = tostring(parse_json(tostring(LocationDetails)).countryOrRegion)
| where isnotempty(SessionId)
| summarize
    DistinctIPs = dcount(IPAddress),
    DistinctCountries = dcount(Country),
    Countries = make_set(Country),
    SignIns = count()
  by UserPrincipalName, SessionId
| where DistinctCountries > 1
| order by DistinctCountries desc, DistinctIPs desc

Q12 · AiTM-related alert roll-up

SecurityAlert
| where TimeGenerated > ago(30d)
| where AlertName has_any (
    "AiTM","adversary-in-the-middle",
    "Anomalous Token","Stolen session cookie",
    "Attacker in the Middle",
    "cookie theft","phishing attack")
| summarize AlertCount = count(),
            FirstSeen = min(TimeGenerated),
            LastSeen = max(TimeGenerated)
  by AlertName, ProviderName, AlertSeverity
| order by AlertCount desc

Response playbook — confirmed AiTM compromise

Immediate · 0–30 min

  1. Revoke all sessions (invalidates refresh tokens)
  2. Force password reset
  3. Disable account if attack is active
  4. Review & remove attacker-registered MFA methods
  5. Block attacker IPs in Named Locations / MDE indicators

Investigation · 30–120 min

  1. Review inbox rules (Forward/Redirect/MoveToFolder)
  2. Audit OAuth app consents for the user
  3. Verify no PIM activations under stolen session
  4. Check mail & file access in CloudAppEvents
  5. Enrich attacker IPs with TI (domain age, AiTM feeds)

Remediation · 2–24 h

  1. Delete malicious inbox rules
  2. Revoke rogue OAuth consents
  3. Block phishing domains (Tenant Allow/Block + MDE)
  4. Re-enable account behind FIDO2/passkey CA policy
  5. Submit phishing URLs to Microsoft
